# PEO -- Prompt Engineering Ontology

PEO (Prompt Engineering Ontology) is an ontology for representing knowledge about
**foundation models, prompt engineering, and prompt-based interactions**.

PEO provides a shared conceptual model for describing foundation models, the tasks
they address, prompting techniques, and interactions with models. Its goal is to
support the interoperable representation and exchange of knowledge about prompt
engineering and to facilitate the reuse of knowledge from previous interactions
with foundation models.

The ontology is designed to support scenarios in which users need to identify
appropriate foundation models and prompting techniques for a given task, as well
as to represent and reuse knowledge about previous prompt-based interactions.

## Main concepts

PEO models the following core concepts:

- **Foundation Model** -- a deep learning model designed to process one or more data
  modalities and solve a variety of tasks through prompting.
- **Model Family** -- a family grouping related foundation models belonging to the
  same model lineage.
- **Architecture** -- a neural network architecture adopted by a foundation model.
- **Data Modality** -- a modality of data that can be processed by a foundation
  model or targeted by a task.
- **Task** -- a problem to be solved on data of a specific modality and potentially
  subject to one or more constraints.
- **Constraint** -- a condition associated with a task.
- **Variable** -- a concept or parameter whose value is constrained by a constraint.
- **Operator** -- an operator specifying how a value is constrained with respect to
  a variable.
- **Value** -- a region representing a value involved in the specification of a
  constraint.
- **Prompting Technique** -- a technique that guides the definition of prompts for
  solving tasks with foundation models.
- **Chat** -- an interaction with a foundation model consisting of prompts and
  responses and addressing a specific task.
- **Prompt** -- a text submitted to a foundation model as part of an interaction.
- **Response** -- a response generated by a foundation model following a prompt.

Together, these concepts make it possible to represent the relationships among
tasks, their constraints and target data modalities, foundation models and their
characteristics, suitable prompting techniques, and concrete interactions with
foundation models.

## Ontology design

PEO was developed following the **LOT (Linked Open Terms) methodology**.

Its conceptualization was driven by competency questions concerning the selection
and use of foundation models and prompting techniques. The ontology is intended
to provide a reusable semantic layer for organizing knowledge about prompt
engineering rather than tying such knowledge to heterogeneous or
application-specific data models.

The current ontology also represents constraints as structured entities that can
be composed from a **Variable**, an **Operator**, and a **Value**, allowing their
components to be represented explicitly rather than encoded as unstructured
strings.

## Example

The following example illustrates how PEO can represent a task constraint stating
that the maximum output length must be less than or equal to 200:

```turtle
:constraint1
    a peo:Constraint ;
    peo:hasVariable :OutputLength ;
    peo:hasOperator :LessThanOrEqual ;
    peo:hasValue :value200 .

:OutputLength
    a peo:Variable .

:LessThanOrEqual
    a peo:Operator .

:value200
    a peo:Value ;
    peo:hasDataValue "200"^^xsd:integer .
